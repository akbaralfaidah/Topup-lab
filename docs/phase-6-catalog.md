# Phase 6 public catalog and search

Phase 6 adds read-only discovery to the Phase 5 homepage. `/products` is the single catalog route. Its `q`, `category`, `availability`, and `sort` GET parameters preserve discovery state in a direct link, refresh, and browser history. `/games/[slug]` is a game-group preview with denomination rows. It has no target input, price, or purchase action. There is no duplicate `/games` listing: the Game category tab at `/products?category=game` serves that purpose.

## Public data boundary

`src/server/public-catalog.ts` projects active categories and products with their public category and brand names. The DTO contains slugs, names, denomination labels, category, game group, display order, and a single customer-facing availability boolean. It contains no provider identity, cost, priority, margin, pricing rule, credential, account, or order field. Game groups are derived from the denomination rows, not stored as invented game products. Homepage discovery now consumes this same projection, so game counts and availability agree on both pages.

Availability is true if at least one mapping for an active product is enabled, marked available, has an enabled provider in HEALTHY or DEGRADED operational state, and is not OUT_OF_STOCK. Otherwise it is false. The UI says “Contoh tersedia” or “Sementara tidak tersedia”; it never names a provider. This reflects the fixed demo configuration, not a live stock promise. The service only runs in non-production demo mode against the established loopback `topuplab_demo_<12 hex>` database. Database failures, live mode, and production mode yield “Katalog belum tersedia.” No exception or connection detail is rendered to customers.

The read uses two parallel projected queries for categories and at most 200 active products, followed by one aggregate availability query restricted to those product IDs. There is no per-product query. Reaching the 200-row boundary fails closed as unavailable rather than silently hiding products; a future larger catalog needs pagination before raising it. React request caching shares the projection between metadata, layout, page, and homepage reads without adding Redis. The 43-product demo remains grouped, so pagination would add friction without useful reduction.

## Search and navigation

`src/lib/catalog-discovery.ts` is the common query and ranking contract. Search trims, collapses repeated whitespace, lowercases with the Indonesian locale, and caps input at 80 characters. The small explicit alias set maps `ml` and `mobile legend` to `mobile legends`, and `ff` to `free fire`. Ranking is exact name, starts-with name, contains name, game-group name, then category name. Stable display order and name break ties. A denomination query such as `86` shows the matching product row; a game-name query shows the game group, avoiding a wall of duplicate game cards. The homepage offers local suggestions from the same ranking function; its native GET form and the catalog's native GET forms work without JavaScript.

Seven visible category tabs map to their URL slugs. Availability can be `all`, `available`, or `unavailable`; sorting can be configured `display` order or `name` A–Z. Unknown values fall back to all/default and are never interpolated into SQL. Search and filters use the bounded public DTO after the parameterized Drizzle reads. Empty results show clear search and category actions. Game cards link to the non-transactional group preview; non-game denomination rows have no false purchase action. All catalog metadata is noindex during the demo phase; category and game canonicals are stable and search/filter variants canonicalize to `/products`.

## Interface and validation

The catalog keeps the Phase 2 ink, chartreuse, typography, radius, and border system. Compact letterform art is original TOPUPLAB treatment, never a game or company logo. Native search, links, selects, and submit buttons retain keyboard behavior and visible focus. Availability uses explicit text as well as color. The homepage suggestion panel uses the established Motion policy and disables its transition under reduced motion; catalog hover color/border uses CSS and also respects reduced motion. There is no decorative loading animation. Server-rendered content remains readable with JavaScript disabled; database unavailability has a deliberate fallback state.

The responsive browser suite checks 320, 360, 390, 768, 1024, 1280, and 1440 px, plus 200% text, no-JavaScript pages, keyboard search/filter operation, reduced motion, and axe. The local PostgreSQL demo tests cover the shared projection and public HTML. Production browser tests verify the unavailable state without connecting to local demo data. Phase 7 product detail, checkout, pricing execution, target input, order/payment/provider flows, and all domain mutations remain out of scope.
